## 资源测量

以下使用十进制 MB。页面内存来自 Chrome memory-infra 的进程私有占用，用页面 user-timing 标记匹配目标 PID；不是 JavaScript heap，也不是整个 Chrome 的内存。

| 场景 | 页面私有内存 | 所有 renderer 的 RSS 合计 | Chrome 所列进程的 RSS 合计 |
| --- | ---: | ---: | ---: |
| 3 项目、初始报告和图表 | 77.4 MB | 493.0 MB | 988.4 MB |
| 3 项目、完成全部功能操作 | 88.4 MB | 523.5 MB | 1,203.4 MB |
| 增加到 15 项目，仅增加元数据 | 90.4 MB | 539.5 MB | 1,256.2 MB |
| 15 项目、重复切换 12 次 | 99.3 MB | 555.4 MB | 1,265.4 MB |

- renderer 数量始终为 3，包含备用/WebUI renderer，不等于三个审查台。
- 空闲两秒时所有 renderer 的 CPU 合计约 0.28%；这是短时采样，不是长期保证。
- 独立打包服务的空闲 RSS 为 57,196,544 字节，约 57.2 MB；监听数为 0。
- 浏览器流程中的服务与测试驱动共享 Node 进程，其 RSS 约 193–197 MB，不能冒充独立服务占用。
- Chrome 全部所列进程的 RSS 包含浏览器、GPU、其他辅助进程和测量开销；RSS 求和会重复计算共享页，不等于实际物理内存总量。整个 Chrome 并不低于 150 MB。

本次页面占用满足规格约定的 150 MB 页面目标。增加项目没有增加 renderer，元数据阶段约增加 2 MB 页面私有内存。有限次数切换未见按项目数常驻完整内容的趋势，但不据此宣称长期无泄漏或所有内容规模都达标。

样本为小型临时仓库和包含公式、Mermaid、函数图的回复，不代表十五个大型真实项目同时满负荷。文件编辑上限 2 MiB，更大文件最多读取 256 KiB 分段；服务测试验证了大文件读取边界。

原始测量和截图保留在 `test-results/performance.json`、`test-results/review.png`，下次执行会更新。该目录不提交；上表记录本次结果。
