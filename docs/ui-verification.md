- 项目行 48 px、改动文件行 28 px、目录行 24 px、diff 行 21 px，以及背景、边线、选中样式按 Paper 的计算样式实现，并检查截图。

- 添加目录保留独立加号和底部入口；移除、排序和收起放进项目菜单，支持点外关闭及 Escape。

### VisualReply：第四栏

从用户现有 VisualReply 服务读取页面，但在独立无头浏览器上下文中操作预览；未连接真实 pi 会话，未触碰用户浏览器的预览历史。

使用同一段 Markdown，将原版页面设为 528×900，与审查台 528 px 右栏对照：

- 正文、一、二级标题的字体、字号、字重、行高、颜色及正文留白逐项比较，全部一致。
- 正文 16.5 px、行高 27.72 px、留白 32/20/80 px；一级标题 27 px，二级标题 21 px。
- 工具条沿用文本按钮、深浅主题及纸色选择；恢复阅读进度与内容统计，保留原有代码、公式、Mermaid、函数图、缩放、复制及消息输入样式。
- 会话与轮次融入原导航位置；原独立页面的浏览器本地 History 不重复作为另一套历史库，轮次由审查台统一导航。
- 原文开关按用户最新决定控制第三栏，而不是原独立页面的内部编辑栏。1050 px 窗口下检查右栏工具条无溢出。

## 已复现并回归的问题

| 问题 | 原因与修复 | 验证 |
| --- | --- | --- |
| 未修改却提示未保存 | CRLF 原文与编辑器规范化后的字符串比较。按原文件换行格式序列化 | 测试先失败；未编辑、完全撤销、保存后切换通过，磁盘换行保持 |
| 回复原文位置不符合约定 | 原文原先挤在第四栏内 | 先用几何位置测试确认失败，再移至第三栏；关闭恢复文件与 Git 历史，草稿不丢 |
| 原文模式 Cmd+S 保存隐藏文件 | 原文件编辑器保留后，旧全局保存快捷键仍能命中它 | 先失败；原文模式保存键只提示临时预览，不保存隐藏草稿 |
| 移除项目后仍读旧会话，目录不刷新 | 服务保留已移除项目的会话元数据，页面据此选回不存在于项目列表的根 | 页面仅选择仍授权的项目会话，切换时清空旧展开路径；移除后外部新增文件能出现在新项目树中 |

还检查了真实文件草稿取消导航、保存期间继续编辑、外部保存冲突、历史只读、跨轮次原文配对、收起后打开原文自动展开、输入法和发送确认、前台监听与服务断线恢复。

### 资源口径

本轮浏览器流程：页面私有内存从 3 项目初始约 87.6 MB，到 15 项目并重复切换后约 106.1 MB。独立打包服务空闲 RSS 约 57.1 MB。空闲两秒 renderer CPU 合计约 0.14%。

这些不是整个应用的总内存。Chrome 所列进程 RSS 合计约 867–1122 MB，包含辅助进程和测量开销，且共享页可能重复计数；浏览器测试中的 Node 进程还包含驱动。没有据此宣称长期无泄漏或所有内容规模达标。
