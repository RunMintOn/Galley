## Problem Statement

当前实现已经能跑通四栏、文件浏览、Git 历史与回复渲染，但看一眼就知道它不是给"一天开几十次"用的：

- 全局等宽字体，连项目名和提交标题都是 mono，10 到 11.5px，读起来碎。
- 所有分区靠 1px 硬边框切满屏，零圆角，层次只能靠线，于是整屏是一张网格。
- 配色带蓝味，增删行的底色是半透明色片叠在灰底上，看起来像脏玻璃。
- 主题样式分别落在应用与继承自 visual-reply 的回复区域。现有按钮已同步切换两处深浅状态；本轮要统一状态来源与视觉令牌，而不是从零增加同步切换。
- 项目列表的第二行显示的是被截断的 `/private/var/...` 绝对路径，十五行完全一样，等于没有副标题。
- Git 历史里看不出某次提交改了多少。要点进详情、逐个文件看完，才知道这条是大是小。
- 现有 Git 界面缺少独立工作区改动入口，无法直接区分已暂存、未暂存、未跟踪内容与提交历史。
- 这一轮的用户消息藏在一个小弹层里，读 diff 时看不到"他为什么要改"。
- 编辑类的临时工作（粘贴两段文本比 diff、临时写一段 Markdown 看渲染）无处落脚，只能开别的应用。

## Solution

把界面按"深色纸面，零阴影，发丝线加背景阶梯"重做一遍，并把三处结构短板补上：本轮上下文回到 diff 上方、Git 列表直接给出每条提交的增删量、工作区改动独立成块。同时新增一个与四栏无关的临时文档界面，支持多标签页的 Markdown 与文本 diff。

四个面板的分工不变：左一是项目，左二是索引，左三是内容，右一是回复。变的是它们长什么样、以及左二在不同模式下装什么。

## User Stories

1. 作为每天要看十几个 agent 项目的开发者，我希望一打开就能看到每个项目当前选定会话的最新轮次改动文件数，这样我不用逐个点进去确认；它不是未读数。
2. 作为开发者，我希望项目列表的第二行显示当前分支名而不是绝对路径，这样我能分清哪一行是哪个活儿。
3. 作为开发者，我希望正在跑的会话用一个绿点标出来，这样我能知道哪个 agent 还在干活。
4. 作为开发者，我希望最新轮次改动文件数是独立数字，不随翻阅旧轮次变化，也不和运行状态绿点混在一起。
5. 作为开发者，我希望界面文字用系统无衬线、代码用等宽，这样长标题和路径读起来不费劲。
6. 作为开发者，我希望所有数字用等宽并右对齐，这样上下对比时位数能对齐。
7. 作为开发者，我希望内容栏看起来像桌上的一张纸，和两侧的导航栏在视觉上分开，这样我知道哪个是"我在看的东西"。
8. 作为开发者，我希望界面没有投影，层次只靠背景深浅和细线，这样深色模式下不会有脏的边缘。
9. 作为开发者，我希望增删行是高饱和的实色块而不是半透明薄膜，这样一眼能分出两种颜色。
10. 作为开发者，我希望有一行显示本轮改了几个文件、加了多少行、删了多少行，以及这一轮的时间范围。
11. 作为开发者，我希望能在平铺和树形之间切换改动文件列表，平铺用于看这一轮，树形用于看目录归属。
12. 作为开发者，我希望在 diff 上方看到这一轮我说过的话，这样我记得 agent 是照着什么改的。
13. 作为开发者，我希望这段用户消息默认展开、可以一键收起，这样它不占地方又随时可用。
14. 作为开发者，我希望 diff 顶部有 Unified 和 Split 两种排布，这样短改动看统一视图、结构性改动看左右对照。
15. 作为开发者，我希望 Split 下同一行的删除和新增左右对齐，旧行号在左、新行号在右。
16. 作为开发者，我希望切到 Split 时自动开启换行，因为这一栏在四栏布局里装不下两列不换行的代码。
17. 作为开发者，我希望有一个 wrap 开关，这样我能自己决定长行是折行还是横向滚动。
18. 作为开发者，我希望 diff 里被跳过的行明确标出"还有 N 行未改动"，这样两个 hunk 头不会贴在一起像是坏了。
19. 作为开发者，我希望 Git 模式的第二栏变成提交列表，这样它和内容栏的分工始终是"索引 + 内容"。
20. 作为开发者，我希望提交列表每一行右侧显示该提交的增删行数，这样我扫一眼就知道哪几条值得看。
21. 作为开发者，我希望提交列表按今天、昨天、更早分组，并显示提交时间和短 hash。
22. 作为开发者，我希望工作区未提交的改动单独成块，放在提交列表上方，这样我不会把"改完了"和"提交了"搞混。
23. 作为开发者，我希望未提交块显示文件数和总增删，并且可以展开看具体文件。
24. 作为开发者，我希望点开一条提交后，看到作者、时间、短 hash 和这条提交的总增删量。
25. 作为开发者，我希望提交详情里每个文件都显示自己的增删量，第一个文件的改动直接展开在文件行下方。
26. 作为开发者，我希望提交详情里不要有需要解释才知道用途的控件。
27. 作为开发者，我希望切到 Git 模式时，审查模式的改动和文件树不会同时挤在第二栏。
28. 作为开发者，我希望回复栏保留 Visual Reply 原有的外观与操作：源码切换、页码、轮次导航、会话状态、输入。
29. 作为开发者，我希望纸色（Charcoal / Ivory）是回复栏自己的属性，可以单独换，不影响应用主题。
30. 作为开发者，我希望应用主题切换时全部区域响应同一主题；主动选择深色主题配 Ivory 亮纸是合法组合，不算主题失同步。
31. 作为开发者，我希望回复栏里的文件路径可以点，点了之后内容栏跳到那个文件。
32. 作为开发者，我希望切换项目时，第二栏和第三栏一起刷新，不会留下上一个项目的残留。
33. 作为开发者，我希望有一个可与四栏审查台同时存在的独立临时文档窗口，可以粘贴两段文本比 diff，或者写 Markdown 看渲染。
34. 作为开发者，我希望临时界面支持多个标签页，用 Cmd+T 新建、Cmd+W 关闭、Cmd+数字切换。
35. 作为开发者，我希望标签页可以横向排列在顶部，也可以纵向排列在左侧。
36. 作为开发者，我希望 Markdown 标签页可以在 Source、Split、Preview 之间切换。
37. 作为开发者，我希望 diff 标签页可以编辑两边的内容，然后切到对照视图看差异。
38. 作为开发者，我希望临时文档不写盘、不持久化；非空内容关闭前确认，取消保留，确认后丢弃，不会写脏仓库。
39. 作为键盘用户，我希望所有主要操作都能用键盘完成，包括切换项目、切文件、翻轮次、开标签页。
40. 作为长期使用者，我希望这两个界面在配色、圆角、字号上完全一致，看起来是同一个应用的两个界面，而不是两个应用。

## Implementation Decisions

### 现有实现是改造对象，不是白纸

仓库里已有一套可运行的实现，包含四栏布局、Git 查询、文件编辑、回复挂载与端到端测试。**本轮替换视觉层、补齐结构、新增临时窗口和桌面外壳，不重写业务后端。** 以下模块保留职责，允许为目标补充查询、调整接口或增加桌面适配：

- 服务与 HTTP 接口层
- Git 查询与 diff 生成
- 文件编辑与草稿保护
- 回复内容的获取与挂载
- 端到端与视觉测试驱动

### macOS 桌面路线与生命周期

- 使用 [egoist/mygo](https://github.com/egoist/mygo#getting-started) 的系统 WebView 路线：Go 管理窗口、菜单、原生快捷键与唤回，HTML/CSS/JavaScript 仍负责界面；macOS 使用 WKWebView，不改写为 Go 原生 UI。
- 首批仅验收 macOS；应用内打包固定版本的 Node 运行时与现有服务产物，从 Finder / Dock 启动无需依赖终端 PATH 或另装 Node。安装体积和实际内存必须测量，不能把 mygo 二进制大小当整个应用大小。
- 两类窗口共用同一个已授权本地服务。沿用现有服务发现、凭证、构建身份检查与后台捕获职责，避免一窗口一服务。现有服务来自不兼容构建时明确提示，不擅自终止或接管。
- 关闭窗口不停止后台服务；`Cmd+Q` 退出桌面外壳，不终止 Agent 或后台捕获。退出前检查所有窗口的文件草稿与非空临时内容，取消退出时保留内容。
- `/review` 启动或唤回单实例审查台并定位会话。应用未运行时也可启动；临时文档窗口独立共存。实际注册、发现和交接机制先在 01 验证，09 完成集成。
- 仅绑定必要的原生能力；继续沿用 Markdown 原始 HTML 关闭、访问凭证和本地服务边界，不能为接入 WebView 放开任意页面的原生权限。
- 先验证现有 CodeMirror、Markdown、公式和图表、剪贴板、中文输入、WebSocket、页面锁与存储在 WKWebView 中的兼容性。Chrome 通过不等于桌面通过。
- 现有文件编辑与草稿保护、多会话选择、引用筛选、合并提交父版本比较、历史全文和 blame 均保留；原型省略入口不代表删除授权。“保留编辑器能力”不扩展为补齐所有编辑器功能。

官方资料核对基线：`egoist/mygo@0cb6d05d55b7c6b73c8bb4ff2fdfd9a6b70a3521`，参见 [getting-started](https://github.com/egoist/mygo/blob/0cb6d05d55b7c6b73c8bb4ff2fdfd9a6b70a3521/docs/getting-started.md)、[windows](https://github.com/egoist/mygo/blob/0cb6d05d55b7c6b73c8bb4ff2fdfd9a6b70a3521/docs/windows.md)、[menus](https://github.com/egoist/mygo/blob/0cb6d05d55b7c6b73c8bb4ff2fdfd9a6b70a3521/docs/menus.md)、[app](https://github.com/egoist/mygo/blob/0cb6d05d55b7c6b73c8bb4ff2fdfd9a6b70a3521/docs/app.md)、[frontend](https://github.com/egoist/mygo/blob/0cb6d05d55b7c6b73c8bb4ff2fdfd9a6b70a3521/docs/frontend.md)。这些是文档证据，不是集成成功的证明；实现时固定经过验证的版本。

### 原型里哪些是设计，哪些是演示残留

原型是 HTML，能跑但没有后端。以下几点**不是**设计，实现时不要照搬：

| 原型里的东西 | 性质 |
|---|---|
| 顶部那条 `Prototype` 开关栏（Theme / Type / Tabs / Paper） | 演示控件，产品里不存在 |
| 15 个虚构项目名与分支名 | 假数据 |
| 提交 hash、`+24 −9`、`+123 −20` 等具体数字 | 假数据，真实值来自 git |
| 回复正文、用户消息原文 | 假数据，真实值来自会话 |
| `Split` 曾标为不可用 | 现有代码已有配对与 Split，但窄于 720px 时禁用；本轮改造为四栏可用并默认换行 |
| 空态文案 "没有打开的标签页 · ⌘T 新建" | 可照用 |

原型中**属于设计**的：字号层级、圆角与间距、配色令牌、行高、状态样式（选中、悬停、折叠）、各头部的信息构成。业务语义、保留能力和桌面行为以本规格为准，原型不是后端或生命周期实现。

布局以 **1440px 内容视口宽**为完整四栏验收基准，优先沿用原型的 196px / 248px 导航栏及弹性内容区，回复栏最低 360px。窄窗口沿用导航栏折叠能力，不能因固定栏宽导致主要操作不可达；窗口最小尺寸与折叠断点由实现根据实测确定并记录。第二栏拖拽不在本轮新增。

### 差异表（现状 → 目标）

1. **字体**：全局等宽 → 界面文字用系统无衬线，等宽只用于代码、路径、数字、hash。
2. **表面**：每栏 `border-right` 硬切、零圆角 → 三档背景（应用底 / 导航栏 / 内容纸），只有内容栏带 12px 外边距与 10px 圆角，其余三栏保持通铺。
3. **配色**：去掉蓝味，改为纯中性灰（`R=G=B`）；浅色同步去掉蓝味。
4. **增删底色**：半透明色片叠加 → 实色深绿 / 深红；增删文字色提高到高饱和。
5. **项目行**：第二行是截断的绝对路径 → 第二行是当前分支名；最新轮次改动文件数为右侧独立徽章；路径进悬停提示。每个项目记住当前选定会话，未选择时沿用现有默认会话规则；翻阅旧轮次不改变徽章，无轮次显示 `—`、确有零改动显示 `0`。
6. **项目栏页脚**：`＋ Add folder ⌘O` 保留为列表末尾的一项，页脚改为监听状态。
7. **改动栏头部**：只显示数量 → 显示文件数、总增删、本轮时间范围，并提供本轮改动列表的 Flat / Tree 切换；完整仓库文件树在下方独立保留，不受该切换过滤。
8. **用户消息**：内容栏头部的小弹层 → 移到 diff 上方，全宽、默认展开、可折叠。显示轮次起止时间；`prompts` 无逐条时间戳，不伪造消息时间。多条消息按报告顺序展示，长文本在区域内滚动，不撑掉全部 diff。
9. **diff 头部**：文件 + 增删 + `n / N` 文件序号 + Unified / Split + wrap。
10. **Split**：复用已有配对实现，解除不适合四栏的宽度禁用并补齐布局。删除行与新增行按顺序左右并排；只有删除时右侧留空，只有新增时左侧留空；上下文行内容相同，但旧、新行号各用其自身编号。每次切入 Split 自动开启 wrap；之后用户可手动关闭并横向滚动，折行后左右对应行仍对齐。
11. **hunk 之间**：新增"还有 N 行未改动"提示行。
12. **Git 模式**：第二栏整栏变为「未提交块 + 提交列表」，第三栏显示选中的工作区差异、提交详情或历史全文。Review 模式下第二栏恢复为「本轮改动 + 完整文件树」。Git 选择不改变右栏会话轮次；回复文件链接沿用打开当前工作区文件的语义，不误开同名历史版本。
13. **未提交块**：新增。按已暂存、未暂存、未跟踪分组，可展开文件并点击查看。已暂存比较 HEAD → index，未暂存比较 index → working tree，未跟踪文本按新增展示；同一路径可出现在两个组，各组按自身基准统计，组文件数不得直接相加冒充唯一文件数。块头显示去重文件数，各组显示自身增删，总增删明确为各组差异量之和而非 HEAD 净变化。忽略文件不展示，保持只读，不新增暂存或提交操作。
14. **提交列表行**：短 hash + 标题 + 时间 + 该提交增删量；按天分组。
15. **提交详情**：顶部卡片含作者、时间、短 hash、总增删；其下为文件行，每行含路径与自身增删；第一个文件的 diff 直接展开在该行下方。
16. **不引入**：原型残留的「Viewed」复选框及 `x / y viewed` 计数不进入产品；不新增已读系统。
17. **不引入外部编辑器跳转**：原型中的「在编辑器中打开」按钮不进入产品；保留现有 diff 打开完整文件、历史全文与「打开当前文件」入口，不能混为同一操作删除。
18. **回复栏头部**：恢复为 Visual Reply 原有构成，包含品牌名、Show source、`⌘/Ctrl + Enter` 提示、主题按钮、纸色选择。第二行保留提交式头（会话短 id、`‹ n / N ›`、Latest reply、连接状态、Input）。
19. **纸色归属**：纸色成为回复栏自身属性，可在 Charcoal 与 Ivory 之间切换，互不影响应用主题。浅色主题下的 Charcoal 是一块浅灰纸，不是深色纸。
20. **主题统一**：应用主题使用单一状态，所有区域同步响应；回复栏不再持有独立的 `.dark` 状态。纸色独立，深色 + Ivory 合法。中性灰要求适用于应用中性表面，不覆盖增删、运行状态及 Ivory 的语义颜色。
21. **模式切换位置**：沿用内容栏头部现有的「本轮 / 历史」两枚按钮，改称 `Review` / `Git`。不新造第三处栏位。

### 数据契约

| 界面元素 | 数据来源 | 现状 |
|---|---|---|
| 本轮改动文件与增删 | 既有轮次报告（ChangeReport） | 已有 |
| 本轮用户消息 | 同一报告里的 prompts 字段 | 已有，位置要挪 |
| 本轮时间范围 | 同一报告的起止时间 | 已有 |
| 未提交文件与增删 | 工作区状态 + HEAD/index/working tree 各自比较，未跟踪文本按新增 | **新增** |
| 提交列表每条的增删 | 新增：提交日志附带逐文件行数统计，一次调用覆盖整页 | **新增** |
| 提交详情每文件的增删 | 既有提交详情查询已逐文件计算 | 已有；不可用和截断不得伪装完整统计 |
| 提交详情作者、时间 | 新增提交元数据，列表与详情使用一致时间口径 | **补充**，现有详情未返回 |
| 当前分支名 | 新增当前 HEAD 状态查询；现有 refs 仅列引用 | **补充**，不能从引用列表猜当前分支 |
| 项目徽章 | 该项目当前选定会话的最新 RoundSummary.count | 已有，调整选择语义，不新增未读数据 |
| 回复正文 | 既有会话读取 | 已有 |

Git 数据要求：

- 使用可无歧义区分记录与路径的查询格式，覆盖二进制、重命名相似度、空格、制表符、换行及非 ASCII 路径。二进制或不可读文本的行数显示不可用，不显示假 `0`；混合统计标记存在不可计数文件。
- 提交列表按页批量获取统计，避免逐提交加载完整详情；合并提交列表默认与第一父版本比较，详情切换父版本后更新统计并标清基准；根提交与空树比较。保留现有分页、引用筛选和项目子目录查询范围。
- 作者时间沿用现有日志口径，按本地时区分为今天、昨天、更早；列表和详情一致。超过文件或读取上限时标明部分结果，不能当完整总量。
- detached HEAD 显示短 hash；非 Git 目录显示非仓库状态但仍能看文件、轮次；尚无提交的仓库仍能显示分支和工作区，已暂存与空树比较。
- Git 数据随前台项目的文件变化和重新聚焦刷新；沿用现有前台监听边界，不扩成所有项目常驻轮询。后台项目分支可懒加载，加载中和不可用状态须区分。
- 本轮仅表示捕获工具的快照净变化，不等于工作区全部变化；保留命令、外部写入未捕获及报告不完整的提示。

### 临时文档界面（独立于四栏）

这是可与四栏审查台同时存在的独立窗口，共用配色令牌、Markdown 渲染能力与 diff 配对算法。本轮不增加同页切换模式；审查台提供可见的打开入口，原生菜单也能打开或聚焦该窗口。

- 标签页：横向顶部或纵向左侧，可通过产品工具栏或菜单切换；去掉 Prototype 栏后仍可操作。新建入口可明确选择 Markdown 或 Diff，`Cmd+T` 默认创建 Markdown；`Cmd+W` 关闭当前标签，`Cmd+1…9` 按序号切换。原生菜单按聚焦窗口派发，审查窗口不执行临时文档标签命令；保留复制、粘贴、撤销、中文输入和文件保存快捷键。
- Markdown 标签页：`Source` / `Split` / `Preview` 三态。Split 为源码在左、渲染在右。预览沿用回复栏的纸张与衬线体系。
- Diff 标签页：`Edit` / `Diff` 两态。Edit 时两侧均可编辑；Diff 时两侧变为只读对照高亮。
  - 两态是本轮范围选择，不是编辑器技术限制。已有 CodeMirror 可支持编辑器装饰；本轮仍只做独立编辑输入与只读对照，不增加实时可编辑高亮 diff。
  - 配对规则与主界面 Split 一致。
- 内容不写盘、不持久化；切换标签、布局、模式或聚焦另一窗口保留内容。关闭非空标签、窗口或退出应用前确认，取消保留全部内容，确认后丢弃；不新增自动保存、崩溃恢复或临时内容日志。临时窗口不应被审查台的浏览器页面交接机制替换。
- 标签页标题可编辑，默认取首行标题或 `untitled`；用户显式命名后不再由首行覆盖。
- 保留可见的新建、关闭、布局和模式入口，不依赖只能靠快捷键发现的功能。临时预览继续关闭原始 HTML，不增加数学公式、图表功能；回复栏已有渲染功能保持不变。

## Testing Decisions

### 好测试的标准

- 只断言用户能看见的事实，不断言实现细节。例如断言“1440px 内容视口下回复栏至少 360px”“Split 自动 wrap 时长行不造成内容区横向溢出”“点击回复路径打开当前文件”；手动关闭 wrap 后允许内容区横向滚动。不用类名或圆角数值代替用户行为验收。
- 视觉部分用截图对照，不写进断言。截图用于评审时看，不用于 CI 判定。
- 新增交互先写会失败的行为测试，再实现。

### 验证边界

1. **主要行为：真浏览器 + 真本地服务 + 确定性 Git 夹具。** 沿用现有驱动覆盖两类界面的行为和已有工作流，不以 DOM 里模拟按键代替原生快捷键验收。
2. **Git 查询：单元测试。** 覆盖新增工作区、提交统计和 HEAD 状态的解析与比较基准，尤其二进制、重命名、特殊路径、根提交、合并提交、无 HEAD 和项目子目录。
3. **桌面集成：真实 mygo / WKWebView。** 验证双窗口共存、原生菜单和按键、关闭/退出取消、单实例与 `/review` 唤回、Node 打包及服务复用。01 先选可复现的最小驱动；能自动化则自动化，否则保留明确步骤、截图和结果，不能只跑 Chrome 即宣告完成。

涉及用户桌面焦点、真实窗口或键鼠操作前先说明影响并取得许可；优先隔离环境。全部夹具使用隔离状态目录和模拟会话，不连接日用 Agent、不修改用户仓库。

### 先例

既有端到端与视觉测试已包含确定性 Git 夹具、真本地服务、真浏览器操作和截图归档。继续复用；只为原生菜单、窗口和 WKWebView 补充必要的桌面验证，不另建重复的网页测试体系。

## Further Notes

### 可运行的视觉基准

同目录下的 `prototype/` 里有两个自包含的 HTML，无外部依赖，浏览器直接打开即可：

- `prototype/review.html`：四栏界面。顶部 `Prototype` 条上的 Theme / Type / View 开关可切状态，**这条开关栏本身不是设计**，见上文残留表。
- `prototype/scratch.html`：临时文档界面。顶部同款开关栏，可切横向/纵向标签页、主题、字体、纸色。

这两个文件是可执行的规格：颜色值、间距、圆角、字号、行高、状态样式全部写在里面，用浏览器开发者工具直接量。**不要重新发明这些数值。**

原型包含可点击的项目、Flat/Tree、Unified/Split/wrap、Review/Git、提交、Show source 和标签页演示。获准实施后先实际点验，区分演示逻辑和真实契约；现阶段仅做过源码摸排，尚未完成浏览器点验或桌面验证。

### 与旧插件的关系

目标终态是一个插件接管两个旧插件的界面职责。本轮只做新界面本身，不动旧插件，不接入日用会话。收编要等新界面在日用里跑过一段时间再谈，避免在没验证价值前重构正在使用的工具。

### 一个会反复出现的判断

这个应用的主要动作是"看一眼"，不是"改代码"。任何新增控件都要能通过这个问题：它是不是让"看一眼"更快了。不能通过的，即使好看也不加。提交详情里移除 Viewed 复选框就是按这条判断做的。

### 延后事项

分支图、从审查 diff 传内容到临时标签页、第二栏拖拽调宽均不阻塞本轮，也不随实现顺带加入。打开或聚焦临时窗口的基本入口属于本轮。
