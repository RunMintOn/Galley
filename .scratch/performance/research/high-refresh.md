# 120Hz 路线调查

调查基线为 `e73c6a3`，目标是持续交互跟上 120Hz，而不只是消除严重卡顿。本文件保存架构对照与测量方法；统一高刷已接入日用包，产品回归和发布证据见[性能记录第四批](../../../docs/performance.md#2026-11-01第四批统一启用-webview-高刷)。

仅在重评 WebView／原生路线、升级 MyGo 或重做合成输出测量时运行本文件的探针。常规构建与高刷回归从 [development.md](../../../docs/development.md) 开始，不依赖历史临时目录。

## 新线索：WebKit 接近 60fps 的页面更新偏好

读取本机新建 `WKPreferences` 的特征列表，查找键名，并用 `_isEnabledForFeature:` 读取默认值：

```text
_features key=PreferPageRenderingUpdatesNear60FPSEnabled default=true
_experimentalFeatures key=PreferPageRenderingUpdatesNear60FPSEnabled default=true
```

只读取了独立进程内的默认对象，没有设置该特征、创建窗口或修改全局偏好。

调查时固定 MyGo 上游的 `internal/darwin/window.go::createWebView` 没有覆盖这一特征。默认值本身**不是整个 Galley 被锁在 60fps 的证明**；下文分别验证页面更新与异步滚动。当前产品构建另应用创建期补丁。

### 上游一手资料

- [WebKit 232702](https://bugs.webkit.org/show_bug.cgi?id=232702)：将该偏好从内部特征调整为实验特征。描述为偏向接近 60fps，而非显示器刷新率。
- [WebKit 294338](https://bugs.webkit.org/show_bug.cgi?id=294338)：请求为 WKWebView 提供 120Hz 支持入口；讨论包括 Safari 设置不等于嵌入式 WKWebView 设置，以及通过私有偏好解锁的实机反馈。

上游评论涉及不同系统与设备，不能直接套用成本机结论。枚举或设置这些特征使用私有 SPI；发现本机存在该特征，不代表已经找到可直接交付的公开 API。

## 桌面对照设计

1. 固定测试窗口所在的 120Hz 显示器、窗口大小与输入脚本。
2. 比较最小页面和实际 Diff 的默认调度与合成输出，先建立能够检出 120fps 差距的测量。
3. 仅在隔离测试实例中，做该偏好的单变量 A/B/A；不调整 Safari 或系统设置，不先修改产品依赖。
4. 使用相同内容测试 MyGo 原生 Diff。原生 frame stats 是构建／绘制／提交成本，不冒充面板实际呈现。
5. 如果输出采样或 Instruments 无法建立可靠的呈现口径，明确报告缺口，不用 rAF 数字替代。

用户回复 `ok` 后执行。测试宿主不是正式 Galley 包：它使用相同固定 MyGo 版本、相同 WKWebView 路径和当前 `dist/web` 前端，直接连接本轮隔离服务。原生分支使用同一 Git patch 的 `editor.DiffView`。没有替换正式包、修改模块缓存或持久化全局偏好。

## 测量方法与探针校正

- 窗口固定为 `(100, 70, 1440, 950)`，完整位于内置屏；没有跨屏测试。
- 最终对照将内容区域固定为宽 510 DIPs，并从该区域取样。原生样式和删除／新增行排列与现有前端不同，不是功能等价替换。
- ScreenCaptureKit 仅过滤本轮测试进程的窗口，关闭指针和音频采集。显式设 `minimumFrameInterval = .zero`，而非默认的 1/60。
- 将窗口缩采样至 720px 宽，对指定内容区域的像素抽样计算指纹。保存输出帧时间、状态与指纹，不保存桌面录像。另保存测试窗口静态截图并已人工查看，确认真实前端与原生 Diff 都显示夹具。
- 指标为窗口合成输出中可观察到的画面变化率，不是面板实际扫描或像素响应；捕获开销、系统调度、事件合并仍可能影响结果。rAF 单独报告，不拿来代替该指标。
- 每轮捕获五秒，统计从首个采样后一秒起的 2.5 秒窗口，避开启动和停滚。滚动方向反转仍包含在统计中。
- 原来的 `test/scroll-wheel.swift` 每次相对等待 8,333µs，还会叠加事件创建／投递成本，因此不能保证输入达到 120 次/秒。研究探针改用 `mach_wait_until` 的绝对截止时间，并记录每次投递的主时钟时间。最终各轮实际约 120.0–120.1 次/秒，间隔 p95 约 8.6–10.3ms；不是无抖动的硬件触控板输入。
- 捕获辅助进程必须先初始化 `NSApplication.shared`；否则出现 `CGS_REQUIRE_INIT` 断言。它使用 `.prohibited` 激活策略，不额外抢焦点。

## 接入与构建约束

- **创建期生效**：现有 WebView 的私有偏好读回变化，不代表调度已变化；本机只有创建前设置才通过 A/B/A。产品接入应维持在 `createWebView` 的配置阶段，不改为页面加载后的设置。
- **构建路径**：当前 MyGo 没有公开的创建期特征入口，所以维护 `desktop/patches/mygo-high-refresh.patch`，正式／测试包共用。直接 `go build` 不会自动应用此补丁；交付使用项目桌面构建命令。
- **Go 1.27**：`-overlay` 不允许替换模块缓存文件。项目构建与研究探针均复制依赖，通过临时 modfile 的 `replace` 编译；仓库依赖声明和模块缓存保持原样。
- **只读副本**：模块缓存复制后，文件和目录权限都可能只读。副本需递归增加当前用户写权限，供补丁替换与清理；仅 `chmod` 目标文件不够。
- **补丁失败检测**：本机 macOS `patch` 曾打印写入失败却返回成功。构建因此另确认目标文件包含补丁后才编译；升级依赖时保留此检查并复跑产品高刷专项。
- **兼容边界**：这是 WebKit 私有 SPI，不是 Safari／系统全局设置。选择器或特征缺失时保留默认调度；尚未验证其他 macOS 版本，不能因本机成功删除兼容检查。

## 最终可复现运行

```sh
npm run build
node --experimental-strip-types .scratch/performance/research/refresh-probe/run.mts
```

入口自动构建探针与 Swift 驱动、生成 Git 夹具和独立服务。需要本轮桌面操作许可和 macOS 录屏／事件投递权限。编译使用正常 Go 缓存，没有旧临时目录前提，不加入默认回归。测试结束关闭自己的窗口和服务，恢复原前台应用；滚动驱动恢复鼠标位置。

主结果为 `test-results/performance/high-refresh/creation/summary.json`，各场景的帧指纹、输入时间和宿主日志也在该目录。最终运行通过往返位置、零内容重建和输入频率检查。静态截图为 `web-default.png`、`native-one.png` 等；只含隔离夹具。

### 创建前偏好的 A/B/A：确认了一层原因

| 最小页面动画 | A：偏好开启 | B：创建前关闭 | A：重新开启 |
| --- | ---: | ---: | ---: |
| 画面变化率 | 59.99/s | 119.98/s | 60.01/s |
| 变化间隔 p95 | 17.33ms | 8.82ms | 17.19ms |
| rAF 间隔中位数 | 17ms | 8ms | 17ms |

前一轮创建前对照也得到约 60 / 120 / 58 次/秒。当前 WebKit 的近 60fps 页面更新策略确实限制这类主线程页面动画；不需要重写 UI 就能解除。这一结果后来用于产品接入，不证明所有 macOS 版本均适用。

### 同口径滚动：不能据此宣称整体根治

以下为最终运行的短样本，不是生产百分位数：

| 场景 | 画面变化率 | 变化间隔 p95 |
| --- | ---: | ---: |
| 真实前端 Diff，默认 A | 92.32/s | 16.98ms |
| 真实前端 Diff，创建前关闭偏好 B | 114.39/s | 9.59ms |
| 真实前端 Diff，恢复偏好 A | 114.78/s | 12.87ms |
| 最小页面滚动，A / B / A | 115.56 / 93.90 / 108.76/s | 9.26 / 16.91 / 16.30ms |
| 原生 Diff，独立进程两次 | 118.61 / 119.59/s | 8.70 / 8.69ms |

关键解释：

- 默认真实 Diff 的 rAF 约 60Hz，但滚动画面可超过 110 次/秒，说明异步滚动不是统一锁在 60fps。
- 真实 Diff 的恢复 A 并没有回到首次 A 的水平；最小页面甚至在关闭偏好时采到更低的滚动画面变化率。因此不能从这批样本得出“关闭偏好稳定改善真实滚动”的因果结论。
- 原生最后两次接近 120 次/秒，说明它是可行候选；但前一轮相同宽度探针也采到约 108.6 次/秒。合成输入与系统调度存在波动，不能将最后两次当成迁移必然收益，更不能把简化宿主当成完整产品。
- 原生最终两次在跳过前五帧后，构建／绘制／提交总成本中位数约 0.8ms，p95 约 1.0ms。这是框架 CPU／提交统计，不是输入延迟或画面呈现时间。不同冷启动的字体和管线缓存状态明显影响第一帧，不做启动速度排名。

## 决策与未决边界

**保留 WebView，先解除已证实的页面更新策略限制。** 原生 Diff 是可行候选，但短样本波动、呈现排列差异及尚未覆盖的产品交互，不足以证明迁移收益。没有选择局部或整体原生重写。

真实触控板手势、输入到画面的延迟、VS Code 同机对照和外接屏仍未测，高刷接入后也尚无用户体感验收结论。研究宿主不是产品交互回归；产品保存／关闭保护等已执行验证以[第四批记录](../../../docs/performance.md#2026-11-01第四批统一启用-webview-高刷)为准。继续诊断应选上述实际症状，不重复把页面 rAF 或单个原生样本当成整体顺滑度结论。
